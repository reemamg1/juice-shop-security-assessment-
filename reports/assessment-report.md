# Web Application Security Assessment Report

## 1. Introduction

This report documents a beginner-level security assessment of OWASP Juice Shop, an intentionally vulnerable web application used for cybersecurity education and practice.

The assessment was conducted in a controlled local environment to explore common web application security issues.

## 2. Assessment Objectives

- Identify and explore common web application vulnerabilities.
- Perform controlled SQL Injection and XSS tests.
- Inspect HTTP traffic using Burp Suite.
- Document observations and suggest security improvements.

## 3. Scope and Environment

**Target Application:** OWASP Juice Shop  
**Target URL:** http://localhost:3000  
**Operating System:** macOS  
**Testing Tool:** Burp Suite Community Edition  
**Additional Tools:** Browser Developer Tools and Docker

All tests were performed locally against the intentionally vulnerable training application.

## 4. Testing Methodology

The assessment involved the following activities:

1. Launching OWASP Juice Shop in a local environment.
2. Exploring the application's login and search functionality.
3. Performing controlled input tests.
4. Observing application behavior.
5. Inspecting HTTP traffic using Burp Suite.
6. Documenting the results and potential security implications.

## 5. Findings

### Finding 1: SQL Injection Test

**Category:** SQL Injection  
**Affected Functionality:** Login page  
**Observation:** A login test involving SQL Injection resulted in successful authentication.

**Security Impact:** If an application constructs database queries unsafely using user input, an attacker may be able to manipulate queries and bypass authentication.

**Recommendation:**
- Use parameterized queries and prepared statements.
- Avoid building SQL queries through string concatenation.
- Apply appropriate input validation.
- Follow the principle of least privilege for database accounts.

**Evidence Status:** The observed login result requires further documentation of the exact input and testing steps.

### Finding 2: Cross-Site Scripting (XSS) Test

**Category:** Cross-Site Scripting (XSS)  
**Affected Functionality:** Search feature  
**Observation:** A JavaScript alert dialog appeared after submitting a crafted search input.

**Security Impact:** If untrusted input is executed as JavaScript in a user's browser, it may expose users to malicious scripts and unauthorized actions.

**Recommendation:**
- Encode output according to its context.
- Avoid unsafe insertion of untrusted HTML.
- Use safe DOM methods such as `textContent` when displaying plain text.
- Apply a Content Security Policy as an additional security layer.

**Evidence Status:** JavaScript execution was observed. The exact execution context and XSS subtype have not yet been confirmed.

## 6. Traffic Analysis

Burp Suite Community Edition was used to inspect HTTP traffic generated by the application.

During inspection, a product search request was observed with an empty `q` parameter.

The browser URL also contained a client-side search fragment. Since URL fragments are not normally transmitted in HTTP requests, the captured request alone does not establish that the tested search input was reflected by the server.

## 7. Limitations

- The assessment was limited to a local training application.
- The exact SQL Injection input and steps require additional documentation.
- The XSS execution context and subtype were not confirmed.
- The findings are preliminary observations rather than a comprehensive security audit.

## 8. Conclusion

This project provided practical experience in web application security testing, including SQL Injection testing, XSS exploration, and HTTP traffic inspection.

It also demonstrated the importance of secure input handling, output encoding, and safe database query practices.

## 9. Disclaimer

This assessment was conducted for educational purposes only against a deliberately vulnerable local application. No third-party or production systems were tested.
